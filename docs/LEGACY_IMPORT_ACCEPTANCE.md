## 两条显式确认路径

1. **直接新账户导入**：选择文件 → 选择La​​imiu实盘核心 → 填新账户名 → 字段/来源/逐条数据预览 → 核对局限并确认。预览不写库。账户创建、事实、ID对应、档案、审计和重算请求在同一事务提交，失败不留半个账户。
2. **先归档后转换**：已存的Laimiu只读档案 → 填新账户名 → 基于当前档案修订重新校验/预览 → 明确确认。原档案逻辑内容、原SHA与第一次预览保持；0058记录revision 1→2与转换凭证，增加账户及旧新ID映射。每份最多转换一次；重复同一确认即使用新幂等键也返回同一账户。final来源拒绝转换成实盘；完整模拟另走0064的独立核验入口。

新预览摘要绑定来源SHA、脱敏逻辑SHA、映射版本、方式、账户名称、逐条数据；转换另外绑定档案ID和expected_revision。更改名称/文件/方式须重新预览。重复文件SHA不再建档或建账户；已归档L来源可使用转换入口。

导入完由主界面刷新账户列表并打开该新账户概览。没有现有账户作为写入目标的API字段。

## 金额、时间和引用规则

- 金额精确到分，价格精确到万分之一，超过精度或非有限值拒绝，不偷偷舍入。
- 原三项成交费用求和作为历史人工费用，同时保留分项。旧待确认记录没有费用字段，仍待确认，导入后的零默认费用须人工核对；不自动确认成交。
- 空现金/空持仓总值保持未知，不把明细之和或零写成原确认事实。快照有已知各项时校验金额关系；别名规范化后持仓重复拒绝。
- 使用规范交易所+代码身份，920证券保留北交所，显式`sh000001`指数与`sz000001`股票分开。原拼写在档案内保留。
- 旧整数成交ID决定同日sequence；旧资金流ID次序由导入时间内微秒序列保持，避免新随机UUID重排同日初始/入金。新created_at表示导入时间，原时间原文留档，不猜时区。
- 日期必须完整合法`YYYY-MM-DD`，不截断带时间值。旧评分仅接受支持维度的0–10整数或null，人工最终分与旧AI建议分开；逐笔必须精确对应同日已导入旧成交ID。坏引用阻止整个核心转换。
- 原净值资料先用当前份额模型验证：缺初始资金、超额出金、无份额的正资产等不能变成确认事实。可改选只读档案保留原内容，再由用户修正来源副本。
- 导入不推断当前持仓/可交易资金、不补原缺失计划目标日期。超卖等历史成交质量仍由新投影显示异常，不伪造缺失买入。

## 脱敏与原件边界

0052存储**脱敏逻辑JSON**，不是原始文件备份。原始JSON字节、SQLite数据库页/WAL/空闲页均不写入新库。记录原文件SHA256和大小、脱敏逻辑SHA256、被清理的字段路径、映射与操作审计。

递归清理已知credential字段，涵盖旧settings的key/value形式、嵌套JSON字符串、常见URL查询密钥/Basic URL凭据/Bearer字符串；不把这些值存入运行设置、预览、审计或幂等响应。格式错误但带credential名称的嵌套JSON字符串整体脱敏。任意自由文字中人为写入的无标记密钥无法穷尽识别，页面明确要求上传前检查。

导出名称为`legacy-sanitized-….json`，内容声明`original_bytes_included=false`，可核对原SHA、逻辑SHA、来源及新旧ID。请自行保留旧文件和附件；脱敏不可逆，不能称该下载可以恢复旧软件全部原始资料。

## 安全与资源范围

- 单文件16MiB，逻辑顶层记录最多5000；超限拒绝，不截断。只接受文件内容与文件名，无服务器文件路径接口。
- SQLite在内存反序列化、query_only、trusted_schema关闭、进度预算、quick_check，只读普通表；不读view/虚拟表，不运行原应用初始化。
- 文件解析/脱敏/校验在写事务外。保存受现有loopback/Host/Origin/session/CSRF/幂等保护；幂等身份只保存摘要，原base64不落库。
- 旧资料档案随SQLite整库备份/恢复；不作为旁路目录文件漏出备份。档案不可覆盖，无删除原件或覆盖当前账户能力。

## 完整旧模拟的显式续用（0064）

新入口位于 sim_state 只读档案详情：填写新模拟账户名 → 核验并预览 → 明确接受缺失历史信息 → 建立独立账户。每份原档案最多迁入一次，同一确认摘要重试返回同一账户；原逻辑档案、第一次预览和原SHA保持。来源修订、逻辑摘要、账户名、normalizer版本共同冻结。

- 只接受真实旧schema1及完整account/config/orders/fills/lots/closed_trades。按原fills顺序逐笔重放；日期不得倒退，成交须唯一对应filled委托的证券/方向/数量/日期/现金影响。
- 初始资金+每笔净成交必须等于当前现金，过程中现金不负；价格×数量、三项实际费用和净金额精确守恒。金额须精确到分，拒绝旧4位金额中确有非零分以下部分。
- FIFO重建每笔买入批次，实际卖出成本/费用/盈亏逐条对照旧closed_trades；剩余数量、单位成本、完整费用和原lots逐项对应。费用分摊不能精确到分时拒绝而非重算。
- 新模拟仍采用100股单位与T+1。旧pending现金未预留，整份续用预览拒绝并解释需在旧资料副本先结算/撤销后重导。取消/拒绝单留只读原档案；同日买卖、未到可用日持仓、原代码别名被旧引擎当多个身份时拒绝。
- 旧历史委托没有真实限价或当时费用快照：价格栏标“旧成交参考，原限价未知”，旧订单config_version=0/config_json={}并携带legacy_origin；实际fill费用为唯一历史费用事实。当前原config只配置后续新订单；旧隐含0.5%预检查不冒充新版cash_buffer，明确从0开始。
- 原schema没有可靠初始日期：只记legacy_sim_import审计，不补造普通sim_account/create起点。账户可继续撮合/卖出，完整历史权益报告仍提示起点未知；不会把首次买入日或导入日猜成初始日期。
- 导出逻辑档案增加simulation_mapping：逐笔旧委托→新订单/成交/批次、核验摘要和边界。原文件始终不变。

## 附件文件对应（0064）

仅对同一来源已迁入的新实盘账户，按原daily_reviews.images索引列出路径和明确新日复盘ID。用户逐项通过文件选择框提供图片；服务只收字节，没有打开原路径、扫描用户目录或任意服务器文件读取接口。

每批最多20张/合计24MiB，单张1B–8MiB；PNG/JPEG/WebP/GIF内容校验和尺寸预算与现有附件一致。预览展示原路径→所选文件→日期/版本、尺寸和SHA；确认绑定来源修订、文件SHA、日复盘revision与已有图片集合。任何并发变动要求重新预览，原选择仍留在页面。只新增或复用同账户同日相同内容，不覆盖正文/其他账户。图片文字和元数据不自动脱敏，用户核对后明确上传；二进制随正式附件备份，base64不记入幂等记录或逻辑下载。
