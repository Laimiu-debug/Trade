# TR-020 交互保障实测

## 范围与复现

2026-09-26 16:40:53（UTC+8），执行 [benchmark_interactive_load.py](../scripts/benchmark_interactive_load.py)：

```powershell
python scripts/benchmark_interactive_load.py --samples 100
```

脚本自动创建独立临时目录、独立真实HTTP应用服务与仅本轮可见的慢HTTP行情源，不读取或写入用户账户。测量结束后通过业务取消接口排空未完成回测/同步，再停止自己的服务。生产代码没有为基准降低持久化或加入等待；SQLite保持WAL、`synchronous=FULL`。逐样本原始输出保存在 [tr020-20260926.json](benchmarks/tr020-20260926.json)。

机器：Intel Core Ultra 7 265K，20核/20逻辑处理器，32GB内存（系统可用物理总量33,592,324,096字节），Windows 11 build26200，Python3.13.15。数据目录在C盘ZHITAI TiPlus7100 1TB NVMe SSD；测量开始空闲约30.45GB。本轮是在正常开发桌面环境执行，主任务的发行包构建也在同时进行，不是关闭所有软件后的裸机成绩。

## 数据与并发负载

- 独立SQLite夹具包含100,000笔成交、5,000篇复盘、10,000条事件仓摘要。摘要明确为早于行情起点的无足够历史记录，没有伪造策略命中或收益。
- 行情为1只证券×1,200根有明确可得时间的日线。队列提交3个不同输入身份的真实Wyckoff V1回测，生产共享调度限制1个CPU计算进程。实测观察到两个实际 `backtest_worker` 子进程先后运行；采样结束时第1个完成，第2个运行，第3个排队，随后明确取消未完成任务。
- 行情同步50只证券，每个上游HTTP响应人为延迟0.6秒；返回合法日线，走生产解析、去重、冻结文件与SQLite写入。只是测试进程替换上游请求地址，不访问公网、不声称真实BaoStock延迟。观测期间24次上游请求完成。
- 3次预热后，循环100次实际HTTP分页GET和复盘PUT，间隔50ms。GET查询事件仓，每页100条，offset在0至8,100间切换；每次PUT写约3KB正文并使用新幂等键和正确修订号，响应包含真实提交结果。
- 100对请求中，**87对**在开始与结束时都有同一个实际回测child PID且同一个上游HTTP请求仍在途。其余13对保留在总样本，未混入严格重叠子样本。全200次交互均成功，无错误或锁超时。

## 测量结果

延迟从发出HTTP请求前计时至完整读取/解析响应；p50/p95采用排序后的nearest-rank（ceil），不包括脚本之间的等待。单位ms。

| 请求 | 样本数 | p50 | p95 | 最大 |
|---|---:|---:|---:|---:|
| 全样本事件仓分页查询 | 100 | 30.56 | 42.86 | 46.60 |
| 全样本复盘保存 | 100 | 14.04 | 23.50 | 29.66 |
| 严格回测+在途行情重叠分页 | 87 | 30.79 | 42.99 | 46.60 |
| 严格回测+在途行情重叠保存 | 87 | 19.70 | 23.45 | 29.66 |

三次回测入队响应分别40.26、15.17、28.99ms。应用进程树采样工作集峰值约231.55MiB（API及其child，非系统级连续峰值）；包括服务启动、预热、采样、取消排空的脚本区间18.61秒，前面的建库/夹具装载不计在请求计时内。

在**这台机器、这些端点和这个负载**下，观测p95低于开发文档的查询300ms/保存500ms目标。目标与测量值分别列明，没有把目标直接写成成绩。

## 尚未证明的范围

- 没有跑5,000证券×1,000日的满市场数据量；这里只验证在真实后台计算与慢I/O竞争下的交互保障，不证明最大任务吞吐、所有接口或长时间饱和下的延迟。
- 分页是事件仓真实服务端offset分页。当前账户成交接口返回账户列表、日复盘列表提供limit；不能把这两者称作已通过服务端分页基准。未来承接这些端点分页时须另测。
- HTTP loopback不包含浏览器绘制、图片渲染、真实互联网延迟，也不等于其他机器/操作系统的SLA。没有人为提高worker并发上限。
- 100个样本是可复现工程基线，不能代替长周期负载、尾部置信区间、磁盘接近满容量或跨平台测试。初次试跑脚本曾因WindowsPath传给psutil类型不符而无法输出，修正后本记录采用完整成功的最终运行。
