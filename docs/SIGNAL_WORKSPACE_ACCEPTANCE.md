# 信号工作区与扫描区间表现

## 交付范围

入口：`/rebuild.html?page=signals`。可从固定行情、保存的漏斗阶段池、已完成通达信任务所冻结的行情显式创建后台扫描，也可直接选择现有多策略扫描。沿用共享 CPU 调度、检查点、取消/继续，不新增无界后台线程。

报告提供发生日、观察确认日、交易 K 线年龄、Active / Expiring / 已过期、同策略排名、事件与风险上下文、T+1 至 T+5 的已观察延迟入场日期，以及交易所/板块/年龄/共振数过滤。跳转原研究时保留 run ID，可继续人工检查待买草稿；报告本身不会创建委托。

保存前预览内容摘要，保存后不可变。历史报告包含扫描请求、策略参数、事件模板快照、原始数据 ID、扫描和子运行摘要、报告算法摘要。删除报告保留扫描与研究；来源扫描后来被删除，已保存报告仍可查看。

## 原代码对照与修正

| 能力 | 原实现 | 新实现和明确边界 |
|---|---|---|
| 年龄 | `app/store.py::_compute_signal_age_days`，观察证券的 K 线日期差 | 沿用观察 K 线计数；事件日不在可见日期中返回未知，不当作 0 |
| 临期 | 原 store 触发日加 2 自然日；`SignalsPage.normalizeSignalRow` 按电脑今日判断 | 保留加 2 自然日规则，但使用报告截至日，历史不会随电脑日期改变 |
| 排名 | `strategy_plugins.py::rank_signals`，store 的同策略排序及 top-N | 原七类加相对强弱五权重、矩阵代理、B1多周期公式逐项对照；完整扫描显式选择旧单股/TDX候选口径，只排名同策略同决策日的所选样本；缺分保持 null |
| 确认 | snapshot 的确认状态和回标事件日期 | 保存观察时间是“此时已观察确认”的上界，不能假装是首次确认时刻；不通过事件回标日提前执行 |
| 延迟 | 原 `entry_delay_days`，涨停套利插件强制 1 | T+1..T+5 是确认/决策之后已观察到的标的交易 K 线；涨停套利保留旧插件固定 T+1。与组合回测额外延后配置区分显示；没有后续行情则待定 |
| 区间共振 | 原 `cross_validate_strategies` 按整个区间各策略出现聚合 | 按证券统计策略数、出现日、次数、逐次分数与原 run；同时保留经过过滤的同日交集 |
| 区间价格表现 | 原 `_calc_range_return_and_drawdown` 错误使用全序列末收盘，回撤循环还先处理区间后的首根 K 线 | `saved-signal-workspace-v2` 只读取区间内已可得收盘，显示实际首末日期、价格与根数；缺失为 null，单根标为 single_bar |

区间收益是价格观察结果，费用未计入，不冒充组合策略收益。可得时间采用原研究 strict 规则，事件、分数的信号输入只取原决策可见前缀；报告截至日之后的价格不参与年龄、延迟或区间统计。

## 完整信号上下文（F23 第二批）

`signal_context.py` / `signal_context_formatters.py` 把原 `get_signals` 的候选、事件、生成门槛与排名接入后台工作进程。新增行为必须显式提交 `scan.signal_context`，未提交时原14种单股观察路径和研究运行身份保持不变。完整路径支持目录内16策略，不能用修改既有结果的 signal 标签代替实际计算。

```json
{"candidate_path":"legacy_tdx","window_days":60,"universe_mode":"strategy_filtered"}
```

- `legacy_store`：至少30根已可得日线；保留全历史涨跌量比、前后10日均量斜率、19次且包含相等的均线比较。
- `legacy_tdx`：至少251根已可得日线；保留近20根涨跌量比、20根首末量斜率、20次严格大于的均线比较。未来文件尾部不能补足历史资格。未知流通股/金额保持缺失，相关质量标签保留；这些字段不被伪造成排名输入。
- `strategy_filtered`：相对强弱五项候选门槛、五龙八项候选门槛、矩阵同日所选池 S1–S4 先行。矩阵S3按规范证券代码升序稳定处理同收益并列，完整候选池摘要进入子运行身份；它仍是旧插件代理公式，不是另一条向量化矩阵引擎。
- `full_market`：承接旧同名模式“跳过策略候选预筛”的语义，范围仍然只是用户选择的冻结样本。实际生成门槛仍执行：例如相对强弱保留收益/回撤/涨跌量比三项，矩阵保留S5或S6。五龙这一路只提供观察，现有模拟草稿仍要求完整入池核对，UI/结果明确说明。
- 全部策略冻结七项通用门槛与实际事件模板ID/修订/SHA/快照；相对强弱另冻结五项排名权重，零值是有效参数。B1真实执行五项原生筛选参数，随后执行完整事件上下文与排名；它与不使用事件门槛的原生B1扫描入口明确区分。
- 原纯格式化方法以静态代码副本承接，不初始化旧存储或访问原数据。保留已有时点、证券别名和非法输入修正：不把未知分数补0，不把无效事件日替换为今日；原Wyckoff明确健康0分继续保留0。B1读取规范证券代码修正旧CandlePoint无代码造成的20cm误判。
- 请求、参数、候选指标、事件模板、矩阵池和计算代码摘要共同绑定任务/子运行。旧保存结果照读；旧计算版本的未完成任务不能混入新代码继续，明确 `CODE_VERSION_CHANGED`，需显式创建新任务。
- 报告过滤只过滤所保存证据，不重新计算候选池。若要改变实际参与矩阵TopN的证券集合，须在扫描来源中重新选择样本并明确重跑。
- 本页支持1至10策略各自参数组合。已保存报告提供“导出此冻结过滤结果 CSV”；未保存的表单修改不影响下载。交叉CSV按原质量分选择各策略代表点（同分最早），不混用策略排名分；见 `RESEARCH_TABLE_EXPORT_ACCEPTANCE.md`。

## 能力限制

- 沿用现有预算：最多 100 个不同证券样本；单日最多 100 次、区间最多 1000 次判断。更大通达信来源必须显式选择子集，不静默截断。
- 当前通达信文件集合及手工样本没有证明历史成分股、退市覆盖或真实当时全市场，报告明确标记未核验。
- 旧单股观察历史不会事后补算完整TDX上下文；缺失分数保持未知。完整扫描显示实际选中的指标口径。
- 没有冻结来源的板块强弱背景、ST状态等仍按实际质量标记说明，不由报告层补造。
- 精确首次确认时刻无法从单个已保存日线快照还原，界面明确使用保存观察上界。
