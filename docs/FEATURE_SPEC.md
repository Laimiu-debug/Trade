## 1. 术语、范围与优先级

- **真实账本**：用户记录已经发生的交易，不向券商发送委托。
- **模拟账户**：在系统内创建委托、撮合与结算，独立资金与持仓。
- **回测实验**：固定历史数据、参数与算法版本的独立运行，结果不记入前两类账户。
- **回合**：同一账户、同一标的从持仓由 0 变为正数，到再次归零的交易集合。
- **待买篮子**：原界面称 ETF 的信号集合及其后续收益跟踪，不等同于真实发行的 ETF 产品。
- **F / L / U**：来源分别为 final-trade / LaimiuTrade / 重构新增的统一能力。表内 U 表示本次设计要求。
- **P0**：数据正确性与主流程基础；**P1**：完整替代旧版必需；**P2**：增强体验与工程完善。优先级仅决定先后，P1 / P2 中的原有功能仍须交付。
- **M0–M7**：实施阶段，具体任务见开发 TODO。功能组的阶段是最晚完成阶段。

## 5. 关键业务规则

### 5.1 同一工具里的三种数据范围

所有交易、快照、资金与统计请求必须携带 `account_id`。账户具有 `kind=real|sim`；回测使用 `run_id`。切换范围清除不适用的选择项，保留各范围自己的过滤偏好。主账户总览不能累加真实与模拟资产。研究信号进入模拟委托草稿，真实交易入口只能创建已发生成交的记录。

### 5.2 交易与回合

1. 交易按 `trade_date → occurred_at（如有）→ sequence → id` 排序，缺少准确时间时不虚构时间。
2. 真实交易允许记录历史事实，交易单位 / T+1 等异常给出核对提示；模拟执行必须遵守选定市场规则版本。默认 A 股普通股票规则承接旧版，特殊品种通过证券元数据表达。
3. 回合使用独立 ID；不能继续以“代码 + 建仓日期”作为唯一身份。更正导致回合拆分 / 合并时保留原关联与摘要修订记录。
4. 闭合回合净盈亏 = 卖出成交额 − 买入成交额 − 全部实付费用。未闭合回合单独展示已实现与浮动盈亏，不能直接计作胜负。
5. 胜率 = 盈利闭合回合数 / 有效闭合回合数。旧版把零盈亏算非胜，兼容视图保留；新版同时显示盈利 / 亏损 / 持平，不让分母含糊。盈亏比为平均盈利 / 平均亏损绝对值，无亏损样本时返回 `null` 并显示“无亏损样本”。
6. 模拟持仓 FIFO 成本、手续费分摊、部分卖出规则与原引擎建立固定样本对照；任何修正记录 `calculation_version`。

### 5.3 单位净值与收益

沿用 L 的顺序：当日出入金视为在当日估值快照之前，按**此前最近有效净值**折算份额。此顺序必须显示在资金账本说明里。

```text
初始有效净值 NAV₀ = 1
有符号资金流 C：入金为正，出金为负
当日份额 Qₜ = Qₜ₋₁ + ΣCₜ / NAVₜ₋₁
有效收盘快照净值 NAVₜ = 总资产 Aₜ / Qₜ（Qₜ > 0）
周期收益 = 期末有效 NAV / 周期开始前最近有效 NAV - 1
回撤 = 当前 NAV / 截至当前历史最高有效 NAV - 1
节点阈值 n = (1 + wave_pct / 100)ⁿ；默认 wave_pct=30，n=1..50
节点当日目标金额 = 当前份额 × 节点阈值
```

例：初始 10,000 元、10,000 份；涨至 11,000 元时 NAV=1.1。再入金 1,100 元新增 1,000 份，总资产 12,100 元，NAV 仍为 1.1。

边界规则：

- 无份额：显示“尚未建立账户净值”，不能将无账户等价为收益 0。
- 资产为零、份额为正：NAV=0 合法，后续按零净值折算出入金不能执行；需要显式结清 / 新建净值段，保留前段历史。距下一节点百分比此时显示不可计算。
- 出金后份额小于零、非有限数、负资产：拒绝并给出字段错误；清仓出金至零保留已结束净值段。
- 无当日快照：可显示最近一次已确认值及日期；估算曲线用虚线和来源标签，不能充作真实当日收益。
- 首周期没有之前估值：从初始建账基准计算并标记覆盖范围。旧版首周期首点算法仅用于兼容对照，不静默混用。
- 节点首次耗时使用自然日；日收益使用有效交易 / 估值日期；周使用 ISO 周年与周号。
- 资金流、快照更正后，从受影响日期重算派生数据，原输入和修订审计保留。

### 5.4 复盘保存与 AI

保存状态：`未修改 → 待保存 → 保存中 → 已保存 / 保存失败 / 版本冲突`。输入停止后自动保存；切日期或路由时先提交或保留恢复草稿。AI 输出单独存为生成版本，包含输入摘要、模型与来源日期；用户接受后生成文档新修订。重复评分保留人工最终分与覆盖标记。

### 5.5 数据与研究可复现

筛选、信号、交叉验证和回测共享证券标识与行情服务；每次运行冻结数据范围 / 内容摘要、截至日、复权、策略版本、参数、事件配置、费用、执行策略及算法版本。不得只保存“当前设置”的引用。新闻与外部行情标明实际来源；本地存储不意味着 AI 或网络行情不会发起外部请求。

## 6. 关键用户流程

| 场景 | 操作序列 | 失败 / 回退 |
|---|---|---|
| 第一次使用 | 建独立数据目录 → 选真实 / 模拟账户 → 初始资金 → 可选行情 / AI → 总览 | 可跳过网络配置完成手工记账；任何步骤不读取旧库写入 |
| 盘后记账 | 选账户日期 → 手录 / 截图 → 待确认 → 核对重复和费用 → 确认 → 更新快照 → 查看回合 | OCR 失败保留图片和草稿；确认失败不出现半条交易 |
| 研究到模拟 | 同步行情 → 筛选 → 信号 / 图表 → 验证 → 委托草稿 → 费用 / 数量核对 → 提交模拟 | 行情过期显式提醒；资金不足逐条返回；不写真实账本 |
| 复盘到计划 | 当日成交 → 手动 / AI 评分 → 正文截图 → 次日预演 → 自动保存 → PDF / 分享 | AI 不可用继续手写；保存失败保留本地恢复草稿 |
| 回测与优化 | 选策略版本 → 配置 / 数据预检 → 提交任务 → 查看进度 → 比较报告 → 保存参数 | 参数点失败与整体失败区分；取消留下状态；应用参数先看差异 |
| 备份恢复 | 生成备份 → 校验清单 → 导入预检 → 看影响范围 → 建恢复点 → 临时恢复验证 → 原子切换 | 任一步失败保留当前库与旧备份；恢复后重启并核对附件 / 回合摘要 |

## 7. 完整性验证方法

开发时为每个 F ID 补充：新实现路径、API 操作 ID、页面入口、验收用例、结果证据、差异说明。原 173 个接口可以合并为新 API，必须保持每个原行为有对应去向。原始 UI 路由、模型声明字段、浏览器持久化文件、脚本、16 个完整策略描述已收入清单。模型字段提取不是完整 OpenAPI，继承字段、校验器与实际行为仍需按来源文件核对。

只有“代码存在”而无运行验证的项目标为待验收。外部服务不可用时，可验证适配器与固定响应样本，但不能声称已通过真实服务测试。后续发现遗漏的现有子功能应补入相应 F ID，不能用编号数量当作删除理由。
