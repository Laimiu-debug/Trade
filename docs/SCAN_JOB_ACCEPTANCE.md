# F26 冻结策略扫描任务验收

## 执行与一致性

HTTP 新建入口为 `POST /api/v1/research/scan-jobs`。旧 `POST /research/scans` 返回 `409 ASYNC_SCAN_REQUIRED`；已有扫描的读取、删除接口及同步领域服务 `create_scan` 保留兼容。

1. 只读准备阶段冻结规范化参数、策略版本和代码摘要、完整事件模板快照、规范证券代码、行情内容摘要及逐日判断计划。
2. 入队只做短事务。共享 CPU 调度器在普通回测、扫描批次、参数搜索点之间轮转；每个进程至多运行一个受限计算子进程。应用单实例锁避免同一数据目录被第二个应用写入。
3. 子进程只读指定行情文件并校验内容摘要，按决策时刻筛选可用 K 线，不访问数据库。每批最多处理一个证券，防止同时载入全部行情。
4. 父进程在写事务外验证结果、尝试标记和输入摘要，再保存私有检查点。只有所有批次完成且全部内容校验通过，才在一次事务内批量写入单股研究、扫描结果及成功状态。
5. 取消、过期工作进程、文件损坏或代码变化都不能发布部分研究信号。已完成检查点尚不可创建交易草稿。

## 资源边界

| 项目 | 当前限制 |
| --- | --- |
| 每次行情 / 单股策略 | 1–100 个 / 1–10 个 |
| 单日 / 区间判断 | 最多 100 / 1000 次 |
| 区间 | 最多 90 个自然日，只计算样本实际交易日 |
| 批次 | 最多 25 次判断、同一证券 |
| 子进程 | 30 秒、512 MiB 内存、1 MiB 输入、2 MiB 输出 |
| 整个任务 | 累计计算最多 600 秒，检查点及发布内容分别最多 16 MiB |
| 扫描队列 | 最多 10 个活动任务；其他领域另有各自队列上限 |
| 取消 | 每 0.1 秒查询取消状态，终止宽限 1 秒；实际响应也受操作系统调度影响 |

调度量子不可抢占。普通回测可能使用完整的 120 秒预算后才让出 CPU；扫描每批、参数搜索每点让出。当前未承诺某个任务的开始时间。通达信逐证券扫描及数据同步仍是各自后台工作流，本验收没有把它们宣称为已经合并到该计算调度器。

## 检查点、备份与恢复

检查点存于 `strategy_scan_chunks`，每块包含尝试编号、连续范围、字节数及 SHA256。它们随现有 SQLite 一致性备份进入归档，无需新临时目录或附属文件格式。

重启会把中断任务重新排队；已提交的检查点保留，未提交批次重新计算。恢复后最终发布仍重新校验全部检查点、原行情文件和执行代码。失败或取消后可显式重试并复用检查点；代码已更新或内容损坏时必须修复输入或创建新任务，不能悄悄换成新版本。

成功发布后清理私有检查点，公开研究结果及扫描记录保留。扫描结果删除不会删除单股研究证据；任务历史仍保留原结果 ID。

## 实测记录

2026-09-26，当前 Windows 本地运行时，一次代表性上限探针：

- 10 个证券，每个冻结样本 2000 根日线。
- 最近 50 个日期，分别运行相对强弱与维科夫策略，共 1000 次判断。
- 40 个真实独立子进程批次，最终成功，用时 **18.089 秒**。
- 发布前全部检查点合计约 **4.52 MB（十进制）**。
- 从 `BEGIN IMMEDIATE` 到 SQLAlchemy `before commit` 事件的事务计时：p95 **3.805 ms**，最大 / 最终发布 **76.193 ms**。

**该计时不包括 SQLite 提交阶段的 fsync，不是 HTTP 响应、保存延迟或生产环境 SLA。** 单个合成样本不代表所有策略组合、磁盘或硬件。计算超时、内存、输入和结果大小限制仍始终生效。
