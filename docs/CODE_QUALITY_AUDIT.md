# 代码检查与优化 · 2026-10-03

本轮检查对象为 `G:\CODE\trade\Trade`，包括统一重构应用、旧版研究界面、旧复盘界面、后端、数据与备份边界、开发及发行脚本。旁边的 `LaimiuTrade`、`final-trade` 作为历史参考，未修改。检查优化阶段保留仓库原有代码和资料；后续按用户要求，将已验收的重构源码、测试、文档与优化变更一并纳入本地 Git 提交，未推送或部署。

## 检查方式

先记录当前分支、文件状态、已有发行包指纹，检查源码语法、架构边界、生成契约、前后端构建和既有测试；再对有证据的问题复现、修复并增加回归。业务检查覆盖交易、研究、复盘、行情、统计和 AI 六个目录的 205 个 Python 模块，重点审查资金与费用、FIFO、T+1、冻结资金、证券身份、研究输入可复现、时间因果关系和 AI 草稿采用边界。另一个审查者复核修改后的会话、备份、数据保存和工具脚本。

“全项目检查”表示覆盖各模块、运行全量自动化和实际应用验收，不表示逐行证明每个策略都无缺陷。外部行情提供方、真实 AI 服务、macOS 包及 Linux 部署需要各自的环境验证。

## 修复与行为变化

| 范围 | 原问题 | 修改后的行为 |
|---|---|---|
| 实盘与模拟证券身份 | `600000`、`SH600000`、`600000.SH` 会被算成不同持仓；别名下单可能无法卖出已有批次 | 计算与查询共用证券身份；SH/SZ/BJ 同数字证券保持独立。原始事实文本、交易 ID、历史研究输入不改写；旧矛盾标记保留独立原始身份，新事实继续严格验证 |
| 统计任务恢复 | 进程中断后保留 `running` 请求，重启仍无法分派 | 重启恢复孤立运行请求，按最新账本版本重算；同版本同输入复用投影，避免重复请求产生假失败；算法版本升级只生成新派生结果 |
| FIFO 性能 | 每笔卖出移除列表头并重复累加全部批次，长账本趋向二次复杂度 | 使用队列和剩余数量累积；保留完整输出及回合 ID |
| 会话 | 前端一直保留旧 CSRF，超过服务端有效期后不能继续请求 | 提前刷新会话；只对明确会话失效响应重连并重试一次，保持原幂等键；网络失败不自动重发账本写入 |
| 重复操作与迟到响应 | 快速重复点击可新增两笔事实；旧账户、报价或保存响应可能覆盖新上下文 | 实盘交易、出入金、快照保存增加同步锁及忙碌状态；异步结果核对账户、日期、字段版本和挂载上下文 |
| 新版数据库及 ZIP 备份 | 仅要求少数表，缺表/列数据库可能被迁移“修复”；部分畸形清单/压缩数据导致 500 | 按已应用迁移版本核对完整表与列，并核对数据库完整性、外键、清单类型、大小及摘要；支持合法旧版本升级，损坏备份按无效备份返回 |
| 旧复盘保存 | 首个编辑可能被跳过，路由离开丢最后编辑，旧日期保存影响当前页面 | 首个脏编辑正常保存；离开时提交最后草稿；明确切日撤销旧定时器；在途保存后串行保存最终草稿 |
| 旧复盘 AI 评分 | AI 新评分可被保存函数捕获的旧数据覆盖；等待期间的编辑可能丢失 | 从最新编辑合并评分，并显式保存新内容；保留并发文本编辑，忽略旧日期的回包 |
| 旧版数据恢复 | JSON 部分验证、覆盖或缺失汇总；密钥可能随导出复制；损坏模拟状态可能被初始化覆盖 | 恢复前独立验证，事务替换失败回滚；兼容合法旧备份；普通导出/导入不传递密钥；损坏状态明确报错并保留原文件 |
| 旧版存储目录 | 运行中移动正在使用的数据库，前端把“复制完成”误当成已切换 | 一致性复制到新目录；复制后停止旧目录业务写入，提示完整退出后重启，显示当前及目标目录 |
| 旧版上传与来源检查 | 同步 AI 调用阻塞事件循环，上传没有合理大小边界；跨来源接口边界过宽 | 同步工作放入线程并使用独立数据库会话；上传限制与本机来源检查 |
| 图片与存储路径 | Windows 图片删除路径可能越界或删除共享引用；含 `#` 数据目录的 SQLite URI 被误解 | 只删除受管且未被其他记录引用的附件；SQLite 使用转义后的只读 URI，不创建错误路径的空文件 |
| 开发与打包 | 启动按端口或进程名结束其他软件；打包失败可能继续显示旧产物；实际要求和文档不符 | 使用空闲本机端口，仅清理自己创建的进程；每个构建步骤检查退出码；清理校验目录边界；统一 Python/Node 要求 |

## 性能证据

24,000 笔成交、12,000 个 FIFO 批次，旧实现和最终修改各运行三次。完整序列化结果逐字节一致，首个回合 ID 均为 `round:b000000`。

| 实现 | 耗时中位数 |
|---|---|
| 修改前 | 1.3056662 秒 |
| 修改后 | 0.0475538 秒 |
| 比例 | 约 27.46 倍 |

数字来自最终兼容修复后的复测，原始三次计时与完整结果摘要见 [基准数据](benchmarks/analytics-fifo-2026-10-03.json)。这只证明该合成 FIFO 场景的计算加速，不能代替完整程序或外部行情的性能测量。

## 开发门禁

- `scripts/check_project_sources.py` 从 Git 已跟踪和未忽略文件生成清单，检查 Python、PyInstaller spec 与严格 JSON；忽略依赖、发行包、运行数据和临时报告。JSONC 的 `tsconfig` 交给 TypeScript 校验。
- CI 检查源码语法、架构边界、设计 token、API 契约、后端全量测试、两个前端的构建及 lint、前端单元测试和浏览器流程。CI 使用 Python 3.13 / Node 22；本地最低 Python 3.11，Node `^20.19.0 || >=22.12.0`。
- 浏览器模拟流程使用独立端口及拒绝连接的 API 代理，避免未模拟请求访问正在运行的真实服务。
- 数据测试使用独立临时目录，包括旧版 `TRADING_MS_DATA_DIR`；运行包验收使用新的状态指针、数据目录及随机端口。
