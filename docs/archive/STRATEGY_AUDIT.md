## 已完成的横向优化

- 研究输入固定数据集内容哈希、策略版本、严格可得时间、参数和代码摘要；代码摘要覆盖计算模块、研究编排与行情可得时间规则。历史运行结果保留当时摘要，新计算逻辑会得到新运行 ID。
- 新迁策略的数值参数按旧目录范围校验，整型参数拒绝小数；布尔参数采用明确的 true / false，参数表单从 schema 读取类型与范围。不支持的旧候选 / 事件参数明确拒绝。研究结果显示质量限制和代码摘要。
- 相对强弱突破入口原先使用统一的 0–10 参数范围，与旧目录逐项范围不符；已修为五个参数各自的范围。趋势为王的 `min_hist` / `min_hist_c` 是历史弹性百分比门槛，旧函数按浮点比较；保留该语义。
- 五龙聚首的原始形态触发与可进入模拟草稿的信号分开；服务端复核入池标记，防止只靠前端隐藏按钮而误提交。
- 涨停套利与涨停梯队统一识别六位代码、市场前缀和 `.SH/.SZ/.BJ` 后缀；修复 20% / 30% 板块被误用 10% 阈值的问题，补齐北交所 `920` 代码。冲突的交易所标记拒绝参与计算，冻结行情 ID 保留。
- 模拟草稿预览、逐笔提交和批量提交按上海时区校验来源研究的决策日期；行情日期较早但研究决策较晚的记录不能提前用于模拟交易，旧草稿也执行该检查。
- 四步漏斗的历史资格改用决策时已可得日线数量，未来文件尾部不再影响历史入池；末根行情日期较早时展示信息标记，供核对休市或数据缺失。
- 矩阵计算、输入池持久化与页面分别落在独立模块；架构检查扩展覆盖所有研究 `*_domain.py`、五龙候选计算和证券代码纯函数。
- 对照测试覆盖真实触发、未触发、板块涨停阈值、可得时间边界、数据不足、参数拒绝及历史结果读取；浏览器验证每个新信号页面。

## 事件与回测口径

- 维科夫 V1 / V2 的插件只透传候选；实际差异在维科夫事件仓快照、阶段、事件日期与评分门槛。现已冻结事件算法版本、模板参数、行情哈希、事件快照和历史可得时间；事件日期与确认时点分别呈现。
- ScoreOnlyRank 读取事件快照的 `entry_quality_score`，并据此判断最低分与排序。现有漏斗的 `score` 或单股形态的 `signal_score` 不是该字段，不能直接代替。
- 矩阵插件已使用同一决策时点的冻结候选池计算 S3；后续还需迁入实际 ATR / 量均比等向量化指标，以及 S8/S9、事件门槛和成交规则。不能将当前插件代理评分当作完整矩阵回测结果。

## 事件、交叉扫描、篮子与统一执行

- `wyckoff_domain.py` 的原始快照与旧分析器逐字段对照；窗口和确认仅使用截止时已可得的日线。`wyckoff_strategy.py` 对照旧 `get_signals` 的实际默认值，V1 默认最低分为 60；V2 的矩阵语义和权重在旧单股扫描中未被使用，此入口明确拒绝。
- 三个系统事件模板、82 个规则及 10 类评分维度从原版导出。系统只读，自定义模板可复制、修改、删除和设为当前；版本冲突拒绝覆盖。每次研究固定完整模板及摘要，改名、改规则和删除均不会改写旧结果。
- 所有 14 个单股策略共用 `runtime.evaluate_strategy`，研究、逐日扫描与统一单股回测调用同一入口。多策略交集按同一证券、同一决策日比较；旧源日期信号保留依据但不计当天命中。每个子判断可单独查看。
- 篮子从手动信号或单日扫描的并集 / 交集构建。同股自动合并多策略证据；历史测算固定篮子修订、行情哈希、费用和截止时间。T+1 / T+2 的原始收益、费用后收益和有效样本数分别报告；同日卖出不给费用后执行收益，缺未来行情保持待定。
- 统一单股执行版本升级为 `next-open-known-prefix-v2`：用 09:30 上海开盘之前已可得的历史日线判断，下一开盘成交；风险观察不能买入。收盘价触发的止损、止盈、跟踪止损在后续开盘执行，避免假设同根日线的高低价顺序。此执行配置与旧组合回测分开标识。
- 回测使用独立子进程，默认 120 秒、512 MiB、输入 4 MiB、输出 16 MiB，预算随任务冻结。取消和关闭会终止本次计算；尝试编号和结果摘要阻止旧尝试、旧代码或未完成结果发布。Windows Job Object 内存限制与真实子进程取消已测试。
- 浏览器走通模板保存 / 应用、维科夫确认与评分、两策略交集、自动篮子测算 / Excel、独立进程回测及刷新读取；320px 研究页无页面级横向溢出。备份恢复保留自定义模板、原研究、删除后的篮子和历史测算。
