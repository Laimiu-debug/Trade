# 策略开发指南

本文说明如何在 **final-trade** 项目中新增一条可选股、可出信号、可回测的策略。后续与 AI 讨论策略时，可直接引用本文，再按清单落地实现。

## 一、策略在系统中的位置

```text
策略文档/口头需求
    ↓
backend/app/core/<name>_strategy.py     # 纯计算：指标 + 触发 + 评分
    ↓
backend/app/core/strategy_plugins.py    # 插件：generate_signals / rank / entry&exit policy
    ↓
backend/app/core/strategy_registry.py   # 注册：strategy_id、参数 schema、默认值
backend/app/core/strategy_ai_meta.py    # AI 可读描述与 playbook（可选但推荐）
    ↓
backend/app/store.py                    # snapshot 挂载 + 信号上下文（reason/分数/等级）
    ↓
backend/app/core/backtest_engine.py     # 回测白名单、入场标签、特殊入场/出场规则
    ↓
frontend                                # 策略参数、信号页文案、回测策略列表、K 线标记
backend/tests                           # 单元测试 + registry/API 冒烟
backend/scripts                         # 专用胜率/诊断脚本（可选）
```

## 二、推荐开发顺序

### 1. 写策略核心（`backend/app/core/*_strategy.py`）

至少提供三个函数（命名可沿用项目惯例）：

| 函数 | 职责 |
|------|------|
| `resolve_*_params(params)` | 合并默认参数与用户覆盖 |
| `calculate_*_signal(candles, ...)` | 从 K 线算出指标快照（挂到 snapshot） |
| `evaluate_*_signal(indicator, params)` | 返回 `{ signal, signal_score, trigger_date, ... }` |

原则：

- **策略内只做「这只票今天是否触发」**，不做全市场涨跌、涨停家数等宏观过滤（那些放在选股范围 / 扫描模式）。
- 板块热度、市值等可作为 **排序加分**，权重宜低，避免误杀新题材。
- 涨停判定用 `market_momentum._is_limit_up` + `limit_up_ratio`，自动区分 10%/20% 板。

### 2. 写插件（`strategy_plugins.py`）

新建 `class XxxPlugin(BaseStrategyPlugin)`：

- `generate_signals`：读 `snapshot["xxx_signal"]`，调 `evaluate_*_signal`
- `rank_signals`：用 `signal_score` + 可选 row 字段（ret40、量比）加权
- `entry_policy` / `exit_policy`（按需）：改写回测 `BacktestRunRequest`（如 `take_profit`、`entry_delay_days`、`exit_events`）

### 3. 注册策略（`strategy_registry.py`）

在 `_register_builtin()` 中增加：

```python
descriptor = StrategyDescriptor(
    strategy_id="your_strategy_v1",   # 全局唯一，建议 snake_case + _v1
    name="中文名",
    version="1.0.0",
    enabled=True,
    capabilities=StrategyCapabilities(
        supports_matrix=False,        # 是否走 Wyckoff 矩阵
        supports_signal_age_filter=True,
        supports_entry_delay=True,
    ),
    params_schema={...},              # 前端参数表单
    default_params={...},
    signal_top_n=10,                  # 信号页每日展示上限
)
self._strategies[descriptor.strategy_id] = descriptor
self._plugins[descriptor.strategy_id] = YourPlugin(descriptor.strategy_id)
```

`params_schema` 字段类型：`number` / `integer` / `boolean` / `enum`（与前端 `strategyParams.ts` 解析一致）。

### 4. AI 元数据（`strategy_ai_meta.py`）

```python
STRATEGY_AI_META["your_strategy_v1"] = {
    "description": "一句话说明逻辑与买卖节奏",
    "playbook": {
        "intent": "策略意图",
        "entry_timing": "例如：信号日尾盘集合竞价",
        "exit_rules": ["次日 +3% 条件单", "连板持有"],
    },
}
```

### 5. 接入 Store（`store.py`）

**5.1 snapshot 挂载** — 在 `_attach_ths_volume_signal`（或同类函数）中：

```python
base["your_strategy_signal"] = calculate_your_signal(candles, symbol=symbol, sector_data=sector_data)
```

**5.2 信号上下文** — 新增 `_build_your_strategy_signal_context`，并在 `_build_strategy_signal_context` 链入：

返回字段需覆盖：`trigger_date`、`signal_name`、`reason`、`entry_quality_score`、`event_grade`、`confirmation_status` 等（可参考 `emotion_limit_up_v1`）。

**5.3 回测扫描**（若需要）— 在策略信号扫描分支里补上 `entry_signal` 文案。

### 6. 回测引擎（`backtest_engine.py`）

- 将 `strategy_id` 加入 `EVENT_INDEPENDENT_STRATEGY_IDS`（不依赖 Wyckoff entry_events）
- 在 `_resolve_event_independent_entry_label` 增加中文标签
- 若有 **特殊入场**（如信号日收盘价买入），加入 `SAME_DAY_CLOSE_ENTRY_STRATEGY_IDS` 并在 `_resolve_entry_index` / 入场价处处理

默认回测参数建议（短线套利类）：

- `take_profit` / `stop_loss` / `max_hold_days`：**只在回测页配置**，策略插件不要写死
- `enforce_t1=True`
- `exit_events=[]`（插件 `exit_policy` 可清空威科夫出场事件）

### 7. 前端

| 文件 | 改动 |
|------|------|
| `frontend/src/shared/utils/strategyParams.ts` | `EVENT_INDEPENDENT_BACKTEST_STRATEGY_IDS`、`OPTIONAL_EXIT_EVENT_BACKTEST_STRATEGY_IDS` |
| `frontend/src/pages/signals/SignalsPage.tsx` | 信号页标题/副标题/列名 |
| `frontend/src/shared/charts/KLineChart.tsx` | 策略 K 线标记 `path`（可选） |
| `frontend/src/mocks/data.ts` | 本地 mock 策略列表（可选） |

### 8. 测试

| 文件 | 内容 |
|------|------|
| `backend/tests/test_<name>_strategy.py` | 核心计算与边界 |
| `backend/tests/test_strategy_registry_plugins.py` | `registry.get("your_strategy_v1")` |
| `backend/tests/test_api.py` | `/api/strategies` 列表包含新 id |

### 9. 专用脚本（可选）

复杂胜率统计可放 `backend/scripts/backtest_<name>.py`，不阻塞主流程。

## 五、涨停套利 `limit_up_arb_v1` 速查

**筛选（策略内）**

- 上一交易日涨停（分板块阈值）
- 当日成交量 ≥ 昨日成交量 × `min_volume_ratio_prev`（默认 1.2）
- 当日涨幅 ≥ `min_day_gain`（默认 3%）
- 可选：`min_volume_ratio_ma5`（默认 0 = 不启用）
- 出场：**不在策略参数里**，使用回测页 `take_profit` / `stop_loss` / `max_hold_days`

**交易节奏**

- 买入：信号日收盘价（尾盘集合竞价近似）
- 卖出：由回测页 `take_profit`、`stop_loss`、`max_hold_days` 决定（策略内不写死）

**脚本回测（出场参数与回测页一致）**

```bash
cd backend
python scripts/backtest_limit_up_arb.py --date-from 2024-01-01 --date-to 2026-06-01 --take-profit 0.03 --stop-loss 0.05
```

**单元测试**

```bash
cd backend
python -m pytest tests/test_limit_up_arb_strategy.py tests/test_strategy_registry_plugins.py -q
```
