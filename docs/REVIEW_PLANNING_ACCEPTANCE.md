# 次日计划与持仓预演（F54）

## 本轮范围

- 每日复盘可从**选定复盘日期**的确认快照复制持仓，或明确选择截至该日的有效入账流水作为基准。复制只修改复盘草稿，沿用原自动保存与版本冲突处理。
- 快照与流水为互斥基准。快照现金未填时保持未知，不用总资产减去不完整持仓推断；流水包括初始资金、出入金、买卖金额和实付费用，排除未来日期及作废记录。缺初始资金或超卖历史时不宣称现金可用。
- 预演数量表示目标持有数量。未列出的原持仓继续保留，清仓须显式填 `0`。同一证券的重复别名拒绝，上海指数 `sh000001` 与深圳股票 `sz000001` 不合并。
- 人工预计价随复盘 JSON 保存，也进入 Markdown/PDF 的预演文本。可另外选择本地冻结行情作为价格假设，严格按复盘日上海时间结束前的可得时间筛选，未来或迟到价格不使用。没有价格时不以零替代。
- 按每个证券的净数量差额估算一笔交易，费用使用账户当前版本设置和共享费用函数。显示佣金、印花税、过户费、预计剩余现金与是否依赖先卖出回款。旧界面未扣费用的现金结果因此可能不同。
- 股数非 100 倍数按现有模拟规则提示；预演不是可执行委托校验，未核验板块特殊申报、涨跌停、停牌、成交概率或分笔最低佣金。费用参数为账户设置，不代表任何日期的最新法定费率。
- 计算接口只读，不创建交易、待确认交易、模拟订单、资产快照或账户费用设置。返回输入与结果摘要；本轮计算结果不作为永久报告保存，改变输入或重新进入页面后需要重算。

## 交易日历与版本差异

新 `local_trading_calendars` 表由迁移 `0047` 建立。用户显式导入 CN_A 日历 JSON，每个自然日必须连续、完整且用布尔值标记是否开市，范围最多 1096 日。保存来源说明、版本、内容 SHA256 和导入审计；更新采用乐观版本校验，数据库备份包含日历和审计。

只有本地完整日历覆盖下一自然日至后续开市日时，界面才提供下一交易日建议；用户点击后才修改草稿。未覆盖、没有后续开市日或超过计划 30 日范围，返回 `unknown`，允许人工指定。来源真实性由用户核对，本功能不会从单只股票缺失行情或“工作日”猜测交易日，也不自动联网。

此前代码会在空目标上使用 `next_weekday`。新记录的空执行日保存为 `null`；已有数据库记录及本机草稿不迁改。旧客户端更新时省略该字段则保留已有日期，显式传 `null` 才清空。计划对照仅匹配已指定的执行日，不再把空值解释成周一。

实际持仓中未写入预案的证券会单独显示“未列入计划”，其计划数量及差额保持空值；这不代表计划清仓。证券关联保留交易所身份，触发条件仍由用户核对。

## 接口与入口

- 每日复盘 → 次日预案：执行日及本地日历导入、持仓预演、现金与费用检查。
- `GET/PUT /api/v1/market/trading-calendar`；`GET /audit`；`GET /plan-date?written_on=&target_date=`。
- `GET /api/v1/accounts/{id}/planning/{day}/baseline?source=snapshot|ledger`。
- `POST /api/v1/accounts/{id}/planning/{day}/preview`：基准来源和 SHA256、目标持仓、明确选择的行情 ID、目标日期。基准/账户事实/费用版本变化返回 `409 PLAN_BASELINE_CHANGED`。

- 架构检查通过：日历/行情在 API 层组合，reviews 接收明确的价格证据与证券比较函数，未扩大领域依赖。
- `frontend/scripts/smoke-review-planning.mjs`：真实 Edge 浏览器通过复制持仓草稿、扣费后现金不足、缺价未知、日历文件导入及手动采用、自动保存、375px 无整页横向溢出。脚本自行启动随机端口和临时数据目录，未修改原应用数据或 8011 的全局日历。
- 上述测试不代表对真实交易日历来源或金融参数的外部验证。
