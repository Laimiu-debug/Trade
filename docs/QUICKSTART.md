# Trade 重构版 · 使用指南

最新 Windows 运行包、校验指纹和实际测试结果见 [发行验收](RELEASE_ACCEPTANCE.md)。新应用入口是 `trade_app` / `rebuild.html`。本文末尾保留旧版启动记录，仅供维护旧应用时参考。

## 1. 启动新应用

### Windows 运行包

可以选择 **单文件 EXE** 或文件夹版，路径见 [发行验收](RELEASE_ACCEPTANCE.md)：单文件版只需复制 `TradeRebuild.exe`；文件夹版须保留整个 `TradeRebuild` 文件夹。双击 EXE 会启动本机服务并打开浏览器；目标机器无需另外安装 Python 或 Node。单文件版启动时会临时展开内置资源，首次打开需稍等。

首次使用建议指定新的独立数据目录与启动器指针：

```powershell
.\TradeRebuild.exe --data-dir "D:\TradeData" --state-file "D:\TradeData-launcher.json"
```

启动器默认尝试 8011 起的空闲端口。Windows 启动后，右下角通知区域会有青绿色 **Trade** 图标；如未直接显示，展开右下角的 **^**。点击图标或右键选择“打开 Trade”可以重新打开页面。

**完全退出：右键 Trade 图标 → 退出 Trade（关闭全部后台）。** 图标在清理完成后移除，随后可以再次双击启动。退出先等待正在进行的写入和后台工作，15 秒未完成则终止本程序拥有的后台进程树；未保存的网页表单需先保存，未完成的任务下次启动时按中断任务恢复。也可使用“系统设置 → 存储与备份 → 服务与目录切换 → 准备退出应用”。仅关闭浏览器标签会保留后台。

重复双击会打开已运行页面；正在退出时会等待释放目录再启动。旧版缺少运行记录时，会核对实际服务身份和数据目录后重开旧页面，换用新版托盘功能仍需先退出旧版。启动失败会显示错误对话框，日志在数据目录的 `startup-error.log` 和 `launch.log`，不会清除账本或强制结束其他软件。

自动化测试和没有桌面的环境使用 `--no-browser --no-tray`。普通双击不需要这些参数。

### 从源码启动

在仓库根目录安装后端依赖，并构建前端：

```powershell
python -m pip install -r backend/requirements.txt
cd frontend
npm ci
npm run build:rebuild
cd ..
python scripts/run_trade_rebuild.py
```

开发环境也可按 [README](../README.md) 分别启动后端和 Vite。新应用默认数据目录为用户目录下 `TradeRebuild`；原项目的数据不会自动迁入。

## 2. 两条日常流程

### 实盘记账与复盘

1. 创建“实盘”账户，录入初始资金及后续出入金。
2. 在交易页录入成交，核对证券、方向、数量、价格与实付费用。OCR 识别会进入待确认区，核对后才正式入账。
3. 保存交易日资产快照，按需填写持仓明细；估算价格只回填表单，须另行保存。
4. 等待重算完成后查看净值、回合、目标节点和周期统计；缺少基线时页面会说明原因。
5. 填写日复盘、评分、次日计划；周/月/回合页整理总结。本机草稿可离线恢复，版本冲突需比较后明确保存。

### 行情、研究与模拟

当前页面已分开：行情的“样本与图表 / 导入样本 / 在线同步 / 数据质量”；研究的策略目录、筛选、扫描、单股/组合回测、参数实验和报告库；模拟交易的下单、结算、草稿、估值、复盘与恢复。组合配置按五步完成，详细入口见 [页面布局说明](UI_LAYOUT_AUDIT.md)。

1. 导入日线、TDX `.day` 或明确发起在线同步。检查证券市场身份、日期范围、来源和可得时间质量。
2. 从“策略研究 → 策略目录”选择任务或具体策略；“选股筛选”提供漏斗、B1、事件/趋势入口。信号工作区的完整上下文模式支持旧策略的通用候选门槛、模板修订与排名权重；多策略组合分别保存参数。新 Donchian、SMA、Bollinger 参考策略使用普通研究/扫描/回测入口，规则见 [经典策略说明](CLASSIC_STRATEGIES.md)。
3. 预览冻结输入后提交扫描/回测/组合任务；任务中心查看进度、错误及支持的取消/暂停/继续操作。
4. 保存报告后查看排名、成交、资金曲线和高级诊断。报告导出使用已保存输入，未保存的表单改动不会改写历史。
5. 将合格研究证据明确转为模拟委托草稿，选择模拟账户并核对数量/现金/费用后提交。模拟成交与实盘账本独立。

固定样本不能代表已核验的历史全市场；未知数据不会补零。日线回测也不能证明分钟内的成交顺序。算法调整和旧版本差异见 [策略口径](STRATEGY_PORTING_NOTES.md)、[组合执行](PORTFOLIO_EXECUTION.md)。

## 3. 数据、设置与导出

- **本地通达信**：“系统设置 → 行情来源”可点击“选择通达信目录”或“扫描本机”，再点“使用此目录”。支持安装目录或其中的 `vipdoc` 目录；选择只在本次运行有效，不保存目录配置。启动时会扫描固定磁盘顶层目录和 Program Files：唯一候选自动使用，多个候选由你选择，深层安装位置请手动选择。检查仅验证本地样本，导入需另外发起。
- **通达信任务恢复**：全市场任务记录数据源指纹以防混用；重新打开后若识别到其他目录，任务会等待你重新选择原目录。取消旧任务后才可改用其他来源。
- **备份**：“系统设置 → 存储与备份”导出完整备份。恢复先预检，再写入新的空目录；确认切换后启动器重启并核对目标。保留原目录和备份，详见 [发行说明](REBUILD_PACKAGING.md)。
- **旧资料**：主动选择原 JSON/SQLite 文件，预览并确认保存档案；可验证的数据可再明确承接到新账户。图片需显式选择原文件并映射，程序不自动扫描个人磁盘。旧报告包使用报告库的旧报告入口。
- **AI**：在统一设置中配置文本/视觉提供方与密钥环境变量名；先显式连接测试。发送前预览上下文，输出须单独采用。没有 AI 配置也能使用账本和手工复盘。
- **导出**：复盘支持 Markdown/PDF/打印，统计支持 PDF/Excel/CSV；筛选可选择阶段、证券和列，回测可导出成交表/资金曲线/报告包。打印署名和本机导出目录见 [导出指南](EXPORT_GUIDE.md)。
- **独立命令**：`TradeRebuild.exe lab --help`、`export --help`、`sync --help`。实验室离线运行；同步/账户导出连接已运行的本机服务。
- **主题**：“系统设置 → 显示与密度”选择浅色/深色/跟随系统及密度。偏好导入先预览差异，正文草稿不包含在偏好文件中。

## 4. 常见情况

- 页面显示“等待后续行情”或“未知”：补充对应日期的数据或保留未知状态，不能把它当作零收益或确认成交。
- 页面长时间打开后，会话会自动恢复；保存期间按钮显示忙碌状态。若请求仍报错，先核对账本是否已有记录，再决定是否重试。
- 任务失败：查看任务中心错误和资源限制；只使用该任务显示的可用重试方式。修改了代码/数据的历史任务可能需要新建实验，旧结果仍可只读。
- 两个标签页内容冲突：保留本机草稿，打开比较后选择采用正式版或明确覆盖；不要手工清除浏览器存储。
- 导出命令不覆盖同名文件：换一个新文件名，或在操作系统里自行管理原文件。
- 外网访问：默认仅本机；需要部署时按 [认证代理说明](REMOTE_DEPLOYMENT.md)，不得把本机接口直接公开。

## 启动步骤

### 1. 启动后端服务

```bash
# 进入后端目录
cd backend

# 启动开发服务器
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

**验证后端是否启动成功**:
访问 http://127.0.0.1:8000/health 或 http://127.0.0.1:8000/api/config

### 2. 启动前端服务

```bash
# 进入前端目录
cd frontend

# 首次运行需要安装依赖
npm install

# 启动开发服务器
npm run dev
```

**前端访问地址**: http://localhost:4173

### 3. 访问应用

打开浏览器访问: **http://localhost:4173**

## 常见问题

### 问题1: 网页打不开

**可能原因**:
1. 后端服务未启动
2. 前端服务未启动
3. 端口被占用

**解决方法**:

1. **检查后端**:
```bash
# 测试后端API
curl http://127.0.0.1:8000/api/config
```

2. **检查前端**:
```bash
# 查看前端日志
cd frontend
npm run dev
```

3. **更换端口** (如果端口被占用):
```bash
# 后端更换端口
python -m uvicorn app.main:app --reload --port 8001

# 前端更换端口
cd frontend
npm run dev -- --port 4174
```

### 问题2: API请求失败

**检查前端配置**:
```bash
# 查看前端API配置
cat frontend/src/shared/api/client.ts
```

确保API_BASE_URL指向正确的后端地址:
```typescript
const API_BASE_URL = 'http://127.0.0.1:8000';
```

### 问题3: 数据加载失败

**检查数据源配置**:
```bash
# 查看当前配置
curl http://127.0.0.1:8000/api/config
```

确认 `tdx_data_path` 是否正确配置。

## 完整重启流程

如果遇到问题，按以下步骤完全重启:

```bash
# 1. 停止所有服务 (Ctrl+C)

# 2. 清理前端缓存
cd frontend
rm -rf node_modules/.vite

# 3. 重启后端
cd ../backend
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000

# 4. 重启前端 (新终端)
cd frontend
npm run dev

# 5. 清除浏览器缓存并刷新
# 按 Ctrl+Shift+Delete 清除缓存
# 或使用无痕模式访问
```
