## 2. 视觉原则

1. **数据可核对**：账户范围、金额单位、时间和来源与数值一起出现；缺失显示 `—` 并提供原因。
2. **主操作明确**：每个任务区域一个主按钮，如“运行筛选”“保存复盘”“确认入账”；次要操作用默认按钮或菜单。
3. **密度可选**：研究 / 回测 / 交易表格支持紧凑密度，正文保持可阅读行长。
4. **长期使用舒适**：低饱和背景、稳定对齐、轻阴影；大块红绿只用于真正需要强调的图表 / 标记。
5. **事实与草稿清楚**：模拟账户、估算资产、过期行情、AI 草稿均用文字标签说明，不只靠颜色。

### 应用图标

- 图形源：`frontend/public/trade-mark.svg`。圆角青绿底、白色 T 与行情柱形，保持小尺寸下可识别；侧栏显示 36px，旁边保留 Trade 文本名称。
- 固定品牌色取自现有令牌：浅色 `brand.accent` 的 `#0f8b6f`、浅色 `action.pressed` 的 `#064735`、深色 `brand.accent` 的 `#71d8b8`、深色 `text.primary` 的 `#e9f1ed`。标志不随明暗主题变色。
- `trade-icon.ico` 包含 16 / 24 / 32 / 48 / 64 / 128 / 256px，均从 SVG 直接渲染；用于 Windows EXE 和浏览器兼容图标。浏览器优先使用 SVG。
- `trade-icon.png` 为 512px 预览 / 素材，`trade-apple-touch-icon.png` 为 180px。以上文件随前端构建复制到发行目录，EXE 从同一份构建快照嵌入 ICO。
- 修改 SVG 后，在 `frontend` 中运行 `npm run icons:rebuild`（使用项目 Playwright，Windows 使用已安装的 Edge），再运行 `npm run build:rebuild` 和 EXE 打包命令。

## 3. 令牌层级与命名

JSON 是本规范的单一数值源。当前采用项目自定义 JSON 格式，**不是宣称兼容某个第三方令牌标准**；由 `scripts/generate_rebuild_tokens.py` 生成前端实际导入的 `tokens.generated.css`。

| 顶层 | 用途 | 单位 / 规则 |
|---|---|---|
| `themes.light/dark.color` | 背景、边框、文字、操作、状态、市场、图表语义颜色 | HEX；遮罩为 RGBA |
| `themes.*.shadow` | 卡片、弹出层、键盘焦点 | CSS box-shadow |
| `font` | 字体族、字号、字重、行高、数字格式 | sizePx 为 px，lineHeight 无单位 |
| `spacePx / radiusPx / sizePx` | 间距、圆角、固定组件尺寸 | px |
| `breakpointPx` | 响应式边界 | px，采用 min-width 断点 |
| `motion` | 时长与曲线 | Ms 为毫秒；减少动态时为 0 |
| `layer` | 叠层顺序 | z-index，统一放在根 portal 层 |
| `print` | 导出与纸面 | Mm 为毫米，Pt 为磅 |

实际代码映射例：`themes.light.color["text.onPrimary"]` → `--text-onPrimary`，`sizePx.control` → `--sizePx-control`。令牌命名以生成脚本输出为准；基础输入框、选择框、复选框、链接与按钮均消费这一份主题值。

数值复用不代表语义可以共用。例如浅色 `status.success` 与 `market.down` 恰好相同，组件仍必须引用各自语义，以便未来独立更改。组件层仅允许角色别名，不允许另一份手写调色板。

### 4.1 颜色与业务含义

- 金额增长 `+1,280.00` 用 `market.up`；亏损 `−320.00` 用 `market.down`；持平显示 `0.00`，不加 `+`。
- “保存成功”用 `status.success`，与盈利无关；“删除交易”用 `status.danger`，不能仅使用涨色表达危险。
- 买 / 卖用文字与三角形 / 标记区分；即便同色也能识别。K 线同时提供涨跌信息和 tooltip。
- 目标节点点亮用品牌强调 + 勾选图标；熄灭用描边 + 状态文字。不要让下降节点成为整页红色告警。
- AI 草稿使用 info 标签；异常交易、估算资产、过期数据使用 warning；不能用柔和颜色掩盖状态文字。

## 5. 字体、数值和空间

| 角色 | 令牌 / 数值 | 排版规则 |
|---|---|---|
| 页面标题 | `font.sizePx.page=24`，600，1.3 | 最多两行，标题与操作同区域 |
| 区块标题 | section=18，600，1.3 | 简短、稳定层级 |
| 正文 / 表格 / 控件 | body=14，400/500，1.5 | 不用 10px 小字承担主要金融信息 |
| 长复盘正文 | reading=16，400，1.8 | 正文段落宽度不超过 760px |
| 元数据 | caption=12，400，1.5 | 来源、日期、单位，不作为主要数据字号 |
| 统计数字 | metric=32，600，1.2 | 等宽数字；货币单位单独以较小字号标注 |
| 代码 / 参数 | font.family.code | 用于代码、哈希、技术参数；股票名称仍为 UI 字体 |

UI 字体：`Segoe UI → PingFang SC → Microsoft YaHei → system-ui → sans-serif`，按平台回退。首屏不依赖网络下载字体。表格数字右对齐，代码左对齐，日期统一格式；百分比、元 / 万元 / 亿元必须有明确表头，不因数值大小暗中改变列单位。

间距基准：4 / 8 / 12 / 16 / 24 / 32 / 48px。20px 专用于默认卡片内边距。控件高 36px；紧凑 32px；触屏交互目标 44px。表头 40px；普通行 44px；紧凑行 36px。圆角：标签 6、控件 8、弹出层 10、卡片 14、弹窗 18；不在页面自由混入其他圆角。

## 6. 统一页面布局

### 6.1 外壳与导航

```text
┌──────── 侧栏 248 ────────┬────────── 顶栏 64 ─────────────────┐
│ Trade                    │ 股票搜索  账户范围  截至日  任务  AI │
│ 总览                     ├────────────────────────────────────┤
│ 市场 / 研究 / 策略 / 回测 │ 标题 + 说明             主要操作    │
│ 交易 / 资金              │ 筛选与上下文                        │
│ 复盘 / 知识              │ 指标摘要                            │
│ AI / 设置                │ 主表 / 图表 / 编辑器 + 详情           │
└──────────────────────────┴────────────────────────────────────┘
```

主内容 padding=24px；宽屏表格占可用宽度；阅读页面居中 max-width=960px。主侧栏按账户复盘、行情研究、工具分组，当前页使用 selected 背景和主色文字。研究内部提供按任务组织的二级导航，一次显示一个子页面，旧 journal 继续并入同一个全局主壳。

### 6.2 四种页面模板

| 模板 | 页面 | 组成与默认布局 |
|---|---|---|
| 数据工作台 | 选股、信号、市场、交易流水、回合 | 标题 → 可折叠筛选 → 简要指标 → 表格；详情抽屉，不强迫全页跳转 |
| 研究实验 | 策略、交叉验证、回测、收益平原 | 配置区 → 校验 / 运行区 → 状态 → 结果；宽屏配置与结果分栏，窄屏上下堆叠 |
| 资产总览 | 首页、持仓、净值、节点 | 4–6 个关键指标 → 主趋势图 → 持仓 / 节点 / 明细；每项标明账户与日期 |
| 复盘编辑 | 日 / 周 / 月 / 回合 | 日期与保存状态 → 自动事实摘要 → 评分 / 人工正文 → 计划 → 附件；大屏可配右侧参考栏 |

标题区只承载标题、说明、上下文与操作。系统诊断、算法 hash 放到“详情”或“数据说明”，不挤占正常录入流程。

### 6.3 各页面的改造要求

| 页面族 | 保留的特征 | 统一方案 |
|---|---|---|
| 总览 / 统计 / 节点 | 净值和目标进度、当日卡片、缺复盘提醒 | KPI 卡统一，NAV / 回撤同一时间轴；节点网格可查看历史 |
| 四步选股 / B1 | 漏斗、独立池和过滤参数 | 步骤条 + 各步结果计数；表单和结果恢复状态明确 |
| K 线 / 分时 | 事件、手动与 AI 标记、区间统计 | 图层控件统一；分析侧栏；图表颜色只取 chart / market 令牌 |
| 趋势 / 梯队 / 资金 / 异动 / 估值 / 新闻 | 各自原有模型与筛选维度 | 统一标题 / 筛选 / 数据截至日；估值字段单位直接显示 |
| 策略 / 事件 / 交叉验证 | 能力、只读参数、策略池、多日共振 | 策略卡与参数表单统一；比较结果有来源列与展开详情 |
| 回测 / 平原 / 篮子 | 原参数、历史、任务、报告与导出 | 配置 / 结果 / 历史分区，复杂参数分组折叠，避免一页连续堆叠全部模块 |
| 模拟交易 / 真实账本 | 下单与已发生交易录入各自语义 | 持续显示账户类型；共用证券、费用、金额组件；动作名称准确 |
| 截图识别 / 待确认 | 原图、识别字段、逐条与批量核对 | 左原图右表单 / 表格，问题行定位；不能把“识别完成”呈现为“已入账” |
| 资金 / 快照 | 出入金、持仓、估算、截图 | 明确已确认 / 估算；余额差异可展开；输入同一数字样式 |
| 日复盘 / 预研 | 当日交易、做 T、六维评分、预演与计划 | 事实摘要、正文、计划三个层级；保存状态常驻；AI 先生成草稿 |
| 周 / 月 / 回合 | 自然周期总结、交易链接、体系迭代 | 相同 ReviewEditor，切换模板字段；相关回合可展开 |
| 标签 / 分享 / 灵感 | 统计、卡片导出、每日温故 | 标签与卡片组件统一；分享预览使用独立打印 / 图片排版 |
| AI 页面 / 抽屉 | 流式会话、上下文、建议与用量 | 全局抽屉 + 完整记录页；上下文可展开，建议用参数差异组件 |
| 设置 / 任务 / 实验室 | 多提供方、数据目录、脚本与进度 | 分类页签；进行中任务非阻断展示；维护动作显示具体作用范围 |

## 7. 组件约定

| 组件 | 必备行为 |
|---|---|
| `PageHeader` | 标题、说明、范围、主操作；窄屏操作换行 |
| `AccountScopeBadge` | 真实 / 模拟 / 回测文字；任何交易与统计区域可见 |
| `DataFreshness` | 来源、截至日、缓存 / 过期 / 估算；未知有解释 |
| `MetricCard` | 标签、单位、数值、比较基准、缺失态；不单靠颜色 |
| `Money / Percent / StockIdentity` | 精度和方向统一；等宽数字、市场前缀、代码复制 |
| `FilterBar` | 提交 / 重置 / 已生效状态；默认值与用户保存偏好区分 |
| `DataTable` | 稳定 row id、排序 / 分页 / 空态、密度、选择汇总；宽列在表内滚动 |
| `ChartFrame` | 标题、单位、来源、图例、加载 / 无数据 / 错误；响应容器尺寸与主题 |
| `ReviewEditor` | 字段模板、保存状态、冲突处理、恢复草稿、AI 版本比较 |
| `ScoreGrid` | 分数 + 文字维度，AI 与最终分分开，人工覆盖有标记 |
| `PositionRehearsal` | 基准日期、现持仓与预演、现金差额、昨日计划对照 |
| `ImportReviewPanel` | 原图与字段对应、疑似重复、错误定位、选中确认 |
| `TaskProgress` | 状态 / 阶段 / 进度、耗时、取消 / 暂停能力；不虚构百分比 |
| `ParameterDiff` | 旧值 / 新值 / 来源 / 校验；明确应用目标与版本 |
| `ActionDialog` | 具体实体、影响范围、主动作；恢复 / 重置同时提供恢复点说明 |
| `EmptyState / InlineError` | 解释原因与下一步；错误不能显示成“暂无记录” |

输入标签放上方并可聚焦控件；必填、单位、提示在字段附近。危险动作不作为默认 Enter 行为；弹窗开关恢复焦点。普通保存用就地状态，不反复弹 Toast 遮挡编辑。

## 8. 图表规范

- K 线：涨 `market.up`、跌 `market.down`、平 `market.flat`；不直接写 AntD 的 success / error。
- MA5 / MA10 / MA20 使用 `chart.ma5 / ma10 / ma20`；同时在图例中写明周期。指标对比使用 `chart.series1..6`，超过六条增加虚线 / 符号差异并允许选择显示。
- tooltip 背景为 `bg.surface`，边框为 `border.control`，正文为 `text.primary`；轴字号 12px、tooltip 13px。
- 网格使用 `chart.grid`，坐标文字 `chart.axis`；净值 / 资金 / 回撤明确单位，不在未说明时共享同一轴。
- 缺失行情不画成零点；插值、近似分时、估算资产采用虚线并标注。
- 买卖、人工标注、AI 标注同时有文字或形状；图表提供数据明细入口，不能只靠颜色读数。
- 主题变化重新生成 option / update 图表；禁止模块加载时一次性读取主题颜色，禁止通过刷新页面切主题。

## 9. 状态、响应式与动效

每页检查：加载中、空数据、正常、有筛选无结果、错误、过期、部分数据、无权限 / 未配置。编辑页面另有未保存、保存中、已保存、失败、冲突。后台任务使用顶栏状态与局部进度；L 原可选全屏 AI 忙碌模式作为偏好保留，但不得挡住取消 / 错误恢复，也不得代替真实任务状态。

| 宽度 | 规则 |
|---|---|
| `<640px` | 单列内容，padding16；触控目标44；指标可两列；筛选折叠；图表工具栏换行 |
| `640–991px` | 侧栏为抽屉；表单 1–2 列；表格内横向滚动；正文优先 |
| `992–1439px` | 常驻248侧栏；主体自适应；编辑器参考栏可收起 |
| `≥1440px` | 复杂研究结果可双栏；复盘正文仍限制阅读宽度 |

无页面级横向滚动；股票代码、负号、数字与单位不被拆成不可读碎片。动效 120 / 180 / 240ms；只用于展开、状态或焦点反馈；`prefers-reduced-motion` 时关闭非必要动画。叠层依次 base0、sticky100、dropdown1000、modal1100、toast1200、tooltip1300；弹层走根容器，避免被图表遮住。

## 10. 对比度与键盘目标

目标：普通正文至少 4.5:1，必要控件边界 / 大字至少 3:1；键盘焦点清晰可见；状态不能仅靠颜色。禁用态不承担重要信息。背景与文本成对检查，不能拿在白底达标的色直接放到任意彩色背景。

本轮对核心配对做了数值计算：浅色主按钮约6.47:1；浅色 muted 文字在 canvas 约4.71:1；深色主按钮文字约9.36:1。**这些是令牌配对检查，不是全应用无障碍认证**。真实页面还需检查字号、焦点、图表标签、disabled 与 hover 叠加状态。

## 11. 打印和分享

使用独立 `print` 令牌：A4、16mm 边距、白底、正文 `#202b26`、次级 `#4f6158`、10.5pt 正文、13pt 节标题、18pt 主标题、1.5 行高。

- 隐藏导航、输入边框、交互按钮；输出账号显示名、日期范围、模板版本和数据截至日期。
- 长表重复表头，标题尽量与下一段同页；长正文允许跨页，禁止整篇套 `break-inside:avoid`。
- 图表输出清晰图片 / 矢量，保持符号与图例；表格的正负号不依赖彩色打印。
- 图片按比例限制宽高；OCR 原图默认不加入分享，用户选择后才加入。
- PNG 分享卡与 PDF 都从同一字段和数值格式器生成；深色屏幕不意味着深色纸面。
- 保留 L 的署名与导出目录偏好，以及 F 的统计 / 报告 / 分享导出类型。
